只調整 GitHub Actions、瀏覽器驗證腳本與文件。遊戲 src、public、模型及建置設定未改；遊戲版本維持 1b806bc4，main 維持 9e6ad3e。

## 已重現問題及處理

- 舊 main 工作 [38133887844](https://github.com/TFCChen/traffic-jam-game-1/actions/runs/38133887844) 的 npm test／build 成功，browser-ci 在 Chrome 啟動探測階段報錯。舊啟動器忽略 Chrome 輸出，固定偵錯埠與十秒輪詢，無法從該次日誌再推定更深原因。
- 啟動器改用 Chrome 分配的偵錯埠及 DevToolsActivePort，最多等候六十秒，同時確認 preview 可用；先開空白頁，兩者就緒後才開遊戲。保留 Chrome 日誌、瀏覽器版本、失敗原因及各階段耗時。
- 新啟動器在 [38194726072](https://github.com/TFCChen/traffic-jam-game-1/actions/runs/38194726072) 成功進入遊戲，隨即重現過期斷言：無效端點會取消選取，而舊測試仍預期保留起點。
- 測試同步目前空白編輯器入口、試玩返回編輯器、備份草稿保存、盤面選車後鍵盤移動、通關演示、離線成功不顯示常駐提示，以及 90° 預設鏡頭。沒有恢復被否決的舊操作。
- 返回編輯器的二百四十毫秒轉場使舊測試提早讀取不存在的欄位；就緒判斷現在也等待轉場結束。逐關重播等待完整出庫後按鈕啟用，再進下一關。
- feature/game-feel 推送現在會執行 CI；原本只監看 main 推送及 pull request，開發分支推送不會直接驗證。
- 本輪輸出集中於忽略的 .browser-checks/ci，GitHub artifact 保留七天。各腳本 JSON 分開命名，不覆寫歷史報告或互相覆蓋。
- 四類瀏覽器測試分開執行且不因另一類失敗而取消，artifact 也各自命名。四十關各自一個工作，加上編輯器／離線、存檔備援、鏡頭，共四十三個工作；每關以隔離的前置通關進度測試當關實際拖曳及新增紀錄。新版本的同分支工作會取代舊工作；已在舊 workflow 啟動的工作不適用新 concurrency 設定。一般 CDP 指令三十秒無回應即提供指令名稱的錯誤，避免無限等待。
- 統一使用同一個 CDP 連線工具，等待遊戲頁面完成、場景就緒及首次 Service Worker 取得控制權，再讀取存檔或重載；關卡面板也等待指定按鈕存在。唯讀輪詢遇到導航中的 execution context 更換可以再讀，其他例外照常失敗，不重試會改變遊戲的操作。
- 精緻畫質鏡頭測試曾在 Page.captureScreenshot 超過三十秒。CI 截圖輸出縮為一半，使用快速 PNG 編碼；只有截圖指令允許一百二十秒，一般操作仍有三十秒上限，畫面與操作斷言保留。
- 鏡頭旋轉驗證分別比較投影寬高／近遠裁面與世界中心，另外確認相機位置有改變；不能把包含 position 的整個診斷物件視為固定投影參數。
- 桌面切成手機尺寸後，等待 renderer 的 viewport 與畫布尺寸一致再取旋轉基準；固定二百毫秒等待曾讀到桌面的 frustum，造成錯誤比較。
- 實測標準畫質的軟體 WebGL 重播前兩關各約九十秒。CI 的四十關大量重播因此使用省電畫質及 800×600，100 次切換也使用省電畫質；實際拖曳、解答步數、通關與存檔斷言保留。編輯器／鏡頭／存檔測試仍涵蓋預設精緻畫質。手動執行驗證腳本仍沿用原尺寸／畫質，玩家設定未改。

Chrome 每次建立專用暫存 profile，結束時只清除此次建立且路徑驗證通過的 profile；不碰正常瀏覽器資料。測試中的清空／損壞存檔、離線和 503 注入皆在 CI 隔離 profile 執行。
