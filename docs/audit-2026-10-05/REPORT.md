# Traffic Jam 全面檢查與改善路線

檢查日期：2026-10-05（台北）。檢查對象：本地新版遊戲，包含本輪巴士、校車與貨車模型。這份報告區分實際操作確認的問題、程式邊界測試，以及尚未實作的美術／體驗建議。

## 結論

核心移車規則、3D 抓取與通關流程已具備穩定基礎。下一階段最有價值的是先固定遊玩構圖、保護編輯草稿及存檔，再統一 UI、減少切關初始化負擔，最後深化美術、燈光與車輛動態。

本輪三款大型車已完成：巴士連續側窗、弧形車頂、行李艙、路線燈與低矮空調；校車獨立短車頭、安全燈、側面安全帶與逃生艙口；貨車分離駕駛艙、貨箱、踏階、後門鎖桿與鉸鏈。輪槽按原本輪距開在車殼側面，玻璃與燈具保持獨立材質批次。

## 驗證範圍與結果

- `npm test` 與 `npm run build` 通過；既有 Three.js chunk 超過 500 kB 的建置提示仍存在。
- 40 個正式關卡全部求解，解題路線逐步檢查是否合法，最後皆達到出口。最慢一次求解加路線重播約 1,405 ms，屬本機樣本。
- 全 40 關實際滑鼠拖曳驗證通過，共 1,029 次合法拖曳；每關步數等於最佳解，通關、下一關與 40 關進度紀錄皆通過。
- 六種角度／尺寸各 24 個抓取樣本通過，無水平溢出、四個棋盤角落在畫面內。
- 第一關觸控九步通關、吸附、受阻、取消、多點觸控取消、三種畫質、獎勵與持續性通過。
- 鍵盤選車、方向鍵移動、復原、設定面板 Escape 關閉與焦點返回，實際操作通過。
- 隔離瀏覽器自製關卡儲存與試玩通過；模擬 WebGL context 遺失後切換到 2.5D 備援，仍可用鍵盤移車。
- 待機約 30 FPS，零待機陰影更新；離屏零繪製。正常流程未看到瀏覽器錯誤。
- 保留使用者進度與設定。自動測試使用隔離瀏覽器、備份／還原測試資料；內建瀏覽器只操作未儲存草稿和可復原移動。

證據檔案：`engine-evidence.json`、`browser-level-evidence.json`、`performance-evidence.json`。可重跑 `node scripts/audit-game.mjs` 與 `node scripts/verify-all-levels.mjs <CDP URL>`。

## 效能紀錄

隔離 Chrome，第一關，標準畫質。拖車日景／夜景／手機夜景 CPU 提交 p95 為 1.7／2.4／2.5 ms，GPU p95 為 6.93／12.65／10.21 ms。繪製呼叫 p95 為 137／137／138。日景三角形 p95 為 169,794，低於前輪 172,082；全部 GLB 共 3,301,932 bytes，較前輪 3,334,748 bytes 略減。

這是短時樣本，CPU 只包括 renderer 提交，未含完整輸入／動畫耗時；GPU 時間會受其他應用與主機狀態影響。手機是桌面 Chrome 尺寸／DPR 模擬。下一輪應增加慢裝置、真手機、長時間連續切關及整段 pointer-to-frame 延遲量測，再決定自適應畫質與更進一步特效。

## 限制與尚待補驗

沒有以照片或單元測試宣稱全面無障礙合規。尚待真手機／低階 GPU、螢幕閱讀器、200% 縮放、弱網／斷網、受限制儲存環境的完整瀏覽器驗證。本輪實際檢查編輯器放置、驗證和草稿離開，並在隔離測試瀏覽器完成儲存、試玩與 WebGL 備援；沒有在使用者瀏覽器新增／刪除儲存關卡。儲存異常是 Node 隔離 mock 測試，不是已重現的使用者資料損壞。

本輪不加入聲音。建議先實作固定遊玩工作區、草稿／存檔保護，再統一 UI 與切關效能，最後深化剩餘車型、街景、光影和車身動態。
