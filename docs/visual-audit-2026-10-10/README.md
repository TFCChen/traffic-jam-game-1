## 值得處理的發現

### 1. 高優先：小螢幕的操作工具列會遮住底排車

**觀察：** 320×568 的縮放條落在停車場右下；844×390 的主操作條跨過停車場最下排。底排深色與青色車輛有一部分被擋住，直接壓縮辨識與點選區域。這是畫面布局問題，不是關卡太擠。

（歷史驗證圖已清理：橫向工具列遮住底排）

**建議：** 鏡頭自動取景要納入工具列真正佔用的安全區域；短螢幕縮放控制可收成一個展開按鈕，或安排在不遮棋盤的邊緣。不要只把整個棋盤無限制縮小。

**驗收：** 上述四個尺寸，預設遊玩視角下 36 格均不受固定工具覆蓋；底排車可看清並拖動，正式遊玩及試玩都需檢查。此輪未修正。

### 2. 中優先：周邊材質和擺設太規整，細看有場景樣板感

**觀察：** 白天展示視角已能看到磚屋、花槽、長椅、棚架與桌椅，內容並不少。問題是大部分步道磚色與明暗接近，樹池、花槽及路緣的接觸處過於乾淨，大片街道也缺乏局部材質變化。

（歷史驗證圖已清理：白天展示視角）

**建議：** 用小幅度磚色差、接縫深淺、樹池土色、路緣局部積塵與少量停留的葉片建立層次；只在周邊增加兩三個能說明場所的小物，例如小屋招牌、盆栽、桌上杯子。精細化現有場景，而不是把同樣物件再複製一圈。

已有地面微紋、污漬與輪跡程式；建議調整實際鏡頭下可感知的尺度與位置，不是從零堆噪點。棋盤內仍應乾淨，避免材質干擾空格判斷。此輪未實作。

### 3. 中優先：場外街道安靜，適合加入低頻的生活事件

**觀察：** 解題與多個場景檢查中，右側街道大部分時間只有路線與斑馬線。既有街景構圖已提供一條很合適的事件路徑。

**建議：** 偶爾一輛背景車沿場外街道駛過，白天可是一台送貨小車，雨景帶克制的輪胎水跡，夜景帶短暫燈光。間隔帶隨機性，同時只有少量事件，不做每幾秒重複的密集循環。紅車出庫期間暫停背景車生成，確保不穿模、不與主角撞線，也不需要新增交通玩法。

目前已有植栽風動、落葉、雨後滴水與小屋暖光（可由場景程式佐證），不是完全靜態地圖。下一輪應先提升這些既有動態的自然度，與背景車共用節奏；不建議加遍布棋盤的粒子、誇張雨滴、閃爍光或移動的格線。省電／減少動態偏好必須能關閉新增裝飾動態。此輪未實作，也未量測其效能。

### 4. 中優先：夜景的場外黑底與深色車輛辨識仍可提升

**觀察：** 夜景路燈的暖色光池已有效果；反向低角度下，深色車的輪廓及底部與場地容易融合。場景板以外幾乎全黑，視覺上更像獨立展示台，街區延續感較弱。

（歷史驗證圖已清理：反向夜景）

**建議：** 加少量低對比的遠處街角／植栽輪廓，或讓場外背景具有柔和色階；使用很弱的環境補光分開深色車與地面，保留路燈暖光作主角。小屋可加入有意義的局部招牌／門窗細節。先比較遊玩俯視與展示視角，避免靠全面提高亮度抹平夜色，也不必加入大片霓虹與強烈泛光。此輪未實作。

### 5. 低優先：兩個容易一起清理的小地方

- 編輯器試玩返回時，已有紅車卻顯示「先在出口列放置紅車」。提示應依草稿狀態選擇，例如「繼續放車，或驗證關卡」。證據：22（原始驗證檔已清理）。
- 設定、收藏與選關的明亮原生捲軸在炭灰 UI 上較突兀；保留可發現性和可捲動性，統一成較細、低對比的深色捲軸即可。小字與未選中項目的對比可同步檢查。證據：02（原始驗證檔已清理）、13（原始驗證檔已清理）、24（原始驗證檔已清理）。未做正式 WCAG 對比量測，不聲稱無障礙全數通過。
