# Traffic Jam

React、Vite 與 Three.js 製作的 6 × 6 移車解謎遊戲。畫面採真正的 3D 模型與光影，規則維持格位式移車：紅車從第 3 列右側離開，一次有效拖曳算一步。

## 功能

- 40 個正式關卡、四種難度、步數、復原、重置與下一關。
- 背景 Worker 最短路徑搜尋、提示、最佳步數與星級評分。
- 自訂關卡編輯器：兩次點選空格放車、選取車輛後移除、驗證、儲存與試玩。
- 九種 Blender 車型：跑車、越野車、皮卡、小轎車、計程車、校車、巴士、露營車與貨運卡車；依車色與長度對應。
- 奶油色厚地台、瀝青紋理、淡輪胎痕、排水溝、立體護欄、出口道路與升降閘門。棋盤外的管理亭、盆栽、交通錐與路燈放在連續的微縮基座上。
- 車漆與玻璃加入一次產生的環境反射；輪胎依移動距離轉動，起停輕微晃動，阻擋時懸吊回彈。倒退亮倒車燈、停住短暫亮煞車燈；四輪保留單一材質批次，以著色器轉動。
- 暖陽、黃昏、霓虹夜景；完成不同的 10 / 20 個正式關卡解鎖後兩種場景，自訂關卡與重複通關不增加解鎖數量。場景選擇保存於瀏覽器。夜景以發光材質及光池呈現，沒有新增投影光源。
- 思考時周邊偶有落葉；通關先抬閘門再加速出場，鏡頭輕微跟隨，最佳步數通關另有彩帶。減少動態偏好會跳過裝飾動畫。沒有加入聲音。
- 怠速排氣、車燈明暗、拖曳煙霧與快速滑動火花；紅車實際駛出出口後顯示通關結果。
- 拖曳時以 13% 不透明度標示整段合法移動範圍，放手後隱藏；選取車輛不會留下舊位置框。
- 拖曳與通關最多 60 FPS、待機動態最多 30 FPS；陰影採 1024px 並在移動時最多每秒更新 30 次。DPI 上限 1.5，離屏或背景頁籤停止繪製，減少動態偏好的靜止畫面不重畫。
- 「視角與光源」可調俯視角 45–80°、左右觀察 ±35°、主光源方向與亮度、投影陰影。新預設 60°／-12°，已存視角保留；「恢復預設」可套用新角度。設定會保存於瀏覽器。
- Raycaster 命中真實車身，拖曳座標反算至地面；視角改變後仍沿原格位移動。
- 車輛選取按鈕搭配方向鍵操作。支援減少動態效果，WebGL 無法使用或中斷時切回 CSS 2.5D。
- 通關紀錄、自訂關卡與視覺設定使用 localStorage；清除網站資料會移除，不跨裝置同步。

## 運行與打包

需要 Node.js 24 與 npm。依賴版本由 package-lock.json 固定。

```bash
npm ci
npm run dev
npm test
npm run build
npm run preview
```

開發網址預設 http://localhost:5173。Windows PowerShell 若限制 npm.ps1，改用 npm.cmd。手機與電腦連同 Wi-Fi，使用開發伺服器顯示的 Network URL 即可測試。

3D 模組以動態 import 載入，GLB 素材另外下載。Three.js 模組仍超過 Vite 的 500KB 提醒門檻；目前沒有離線快取。手機加入主畫面由 manifest 支援，尚無 Service Worker。

## Blender 素材

`art/toy-garage.blend` 是可編輯的模型原始檔，包含停車場與九種車型。遊戲讀取 `public/models/` 的 GLB，修改 .blend 不會直接更新遊戲；需將對應模型匯出為相同檔名的 GLB。保留車型尺寸、原點、Paint 材質名稱，以及 GLB 的 Y-up 轉換。Rolling wheels 材質批次需保留頂點色；本地四輪中心依車長、固定輪距與 .19 格輪半徑設定於 garageMaterials.js。若改變輪距或半徑，需同步修改動畫參數。

`scripts/build_models.py` 可用 Blender 4.5 重新產生全部素材：

```powershell
& 'C:/Program Files/Blender Foundation/Blender 4.5/blender.exe' --background --python scripts/build_models.py
```

重新產生會覆寫 .blend 與 GLB。若已手動修改，先另存原始檔，或將修改整合回產生腳本。車型沿本地 X 軸向前；Blender Z-up 匯出後為 Three.js Y-up，長度 2 或 3 格、寬度小於 1 格。

## 驗證

`npm test` 檢查移動規則、解題路徑、評分、40 關資料，並解析九個 GLB 檢查尺寸、地面高度、Paint 材質及所有關卡的車型長度對應。GitHub Actions 在 PR 與 main 更新時測試和打包。素材測試亦檢查四輪頂點色與旋轉中心，場景測試檢查解鎖門檻及排除自訂／無效進度。

`scripts/check-vehicle-hits.js` 在載入遊戲的瀏覽器中執行：3D 模式檢查每台車三個車身位置的射線命中；2.5D 備援檢查五個表面位置與棋盤軸線。

```powershell
agent-browser --session traffic-jam open http://localhost:5173
Get-Content scripts/check-vehicle-hits.js -Raw | agent-browser --session traffic-jam eval --stdin
```

`scripts/check-scene-performance.js` 可同樣透過 eval --stdin 在靜止的 3D 關卡執行，檢查待機影格上限、陰影快取與離屏停止及恢復。此輪相同環境 3 秒待機繪製呼叫從 22,841 降至 5,964；此數據代表測試環境，並非所有裝置的 FPS 保證。水平與直向拖曳範圍及優化後第一關九步通關已以滑鼠驗證。

此瀏覽器檢查需另行執行，仍需實際拖曳與通關驗證。本輪已在 45° / 35° 視角以滑鼠完成第一關九步通關，於 375px 畫面建立並試玩自訂關卡，檢查 320px / 80° / -35° 車身命中、設定保存、鍵盤移車、復原及 WebGL 中斷備援。本輪另以滑鼠確認倒車燈、煞車燈、輪胎角度及完美通關彩帶／鏡頭跟隨，以隔離測試資料確認 10 / 20 關解鎖和場景保存。55° / 35° 夜景的 375px 命中與無橫向溢出通過，待機影格上限、陰影快取及離屏停止保持通過。尚未以實體手機驗證觸控與效能。

## 程式結構

- `src/main.jsx`：遊戲畫面、關卡、操作與編輯器。
- `src/Board.jsx`：3D 畫布、載入備援與視角光源設定。
- `src/garageScene.js`：Three.js 攝影機、模型、光影、命中、拖曳及動畫。
- `src/Board2D.jsx`：CSS 2.5D 備援棋盤。
- `src/vehicleModels.js`：車色與長度對應車型。
- `src/garageMaterials.js`：程序紋理與合批車輪的著色器動畫。
- `src/sceneThemes.js`：場景光照與正式通關解鎖條件。
- `src/GameUI.jsx`：按鈕圖示、通關結果與焦點處理。
- `src/gameEngine.js`：格位規則、驗證、搜尋與評分。
- `src/solverClient.js` / `src/solver.worker.js`：可取消的背景解題。
- `src/storage.js`：進度與自訂關卡。
- `src/styles.css`：桌面與手機介面。
- `public/levels/`：40 個關卡與索引。
- `public/models/`、`art/`、`scripts/build_models.py`：遊戲素材、Blender 原檔與產生腳本。

開發分支透過 PR 審查後合併；GitHub origin 為 https://github.com/TFCChen/traffic-jam-game-1.git。Vercel 發布後需確認部署結果。

## 介面、收藏與畫質

遊戲改用深色車庫 HUD，移除網頁標題／介紹與外框卡片；關卡與步數集中在頂部儀表，操作列在棋盤下方，全螢幕高度的場景保持主要按鈕可見。關卡、分析、自訂關卡與收藏集中於抽屜。車庫設定另有抽屜，可用 Esc 或背景關閉，並恢復原按鈕焦點。手機版保留安全區與 44px 主要操作按鈕。

車輪維持貼地，只有車身繞輪軸高度的獨立樞紐作加減速俯仰；使用臨界阻尼、平滑速度與加速度限幅。標準強度角度上限 0.02 rad（約 1.15°），長車反應縮為 78%；「車身動態」滑桿可調 0–150% 並保存。受阻／煞停有單次接觸脈衝與煞車燈，不套用來回正弦震動。這是受格位規則約束的視覺動態，並非自由剛體碰撞模擬。`vehicleDynamics.test.mjs` 檢查 30/60/120 Hz 穩定性和單側脈衝回正，觸控整合測試檢查受阻位置不變、可見俯仰、回正及輪胎不傾斜。

街角場景增加人行道、路緣、街道標線、行穿線、小亭遮棚、長椅、垃圾桶、樹冠和維修蓋，出口保留通行空間。周邊材料較低飽和，中央車輛保持清楚；夜景使用中央柔光與周邊暖色燈池。車模增加斜面玻璃、清漆車漆、下緣飾條／雨刷與柔和接地陰影。模型繼續依材質合批，出庫增加少量尾煙與輕微鏡頭跟隨，關卡載入使用淡入；減少動態偏好仍受尊重。

畫質提供精緻（DPR 上限 2、2048 陰影）、標準（1.5、1024）及省電（1、關閉陰影／裝飾待機動畫，拖曳上限 30 FPS）。偏好仍存於瀏覽器。觸控先判定真實模型；沒命中時才以投影車身周邊 12px 容錯，放手約 0.42 格即可吸附，合法移動範圍不變。

收藏包含首次通關、三星、最佳步數、十關與四十關徽章；黃昏／夜景依十關／二十關解鎖。新收藏顯示於通知與通關結果，重玩不重複增加。既有紀錄保留，最佳步數徽章從本版實際完成的最佳解開始記錄。

`node scripts/verify-touch.mjs <CDP-WebSocket-URL>` 可在開啟 localhost:4173 的隔離 Chrome 測試瀏覽器中，透過真實觸控事件驗證容錯、吸附、取消、三檔畫質、九步通關與第十關解鎖；完成後還原進度／偏好。此為模擬裝置測試，實體手機仍待驗證。

## 拖曳效能與素材預算

車身動態的新預設為 120%，已保存的偏好仍保留。車輛飾件、街景及閘門使用頂點色合批；車漆、玻璃、車燈與轉動車輪保持獨立。小零件依尺寸減少倒角段數，主要車身輪廓保留。前一輪純效能優化將全部 GLB 由 4,068,088 bytes 降至 2,024,420 bytes；加入精修車模、內裝、主角跑車、掀背小車、越野車及圓管圍欄後為 3,334,748 bytes，仍較原始細節版本少約 18%。標準與省電畫質使用較輕的車漆及不透明車窗，精緻畫質保留清漆層與透明玻璃。

拖曳使用累積影格截止時間，避免微小排程延遲反覆跳過影格；懸停命中檢查最多每秒 20 次，按下及拖曳仍即時處理。靜止陰影快取、待機 30 FPS 與離屏停繪保持通過。素材測試另檢查合批前後包圍盒，防止尺寸或變換偏移。

上一輪純效能優化（c373947）的量測：單一隔離 Chrome、第一關、標準畫質、1280×900、DPR 1，對照提交 6930778。以下為歷史對照，精修版繪製量需重新量測：

| 指標 | 優化前 | 優化後 |
| --- | ---: | ---: |
| 待機每幀繪製呼叫中位數 | 105 | 68 |
| 拖曳每幀繪製呼叫中位數（日景） | 198 | 124 |
| 拖曳每幀三角形中位數（日景，含陰影） | 262,054 | 109,958 |
| 拖曳 CPU 提交時間 p95（日景） | 4.0 ms | 2.7 ms |

此短時測試不是通用 FPS 保證；GPU 日／夜景時間有波動，夜景尚未確認穩定改善。手機尺寸測試是桌面 Chrome 模擬，實體手機仍待量測。

`node scripts/benchmark-render.mjs <CDP-WebSocket-URL> <output.json> [base-url]` 在隔離測試瀏覽器中以實際滑鼠拖曳比較日景、夜景與手機尺寸，完成後還原進度及偏好。預設網址 localhost:4173。先關閉其他 3D 測試頁，避免同時佔用 GPU。診斷預設關閉；`garageInspection.measure(true)` 才啟用 CPU 提交計時與非同步 GPU 查詢，結果位於 `snapshot().performance.profile`。CPU 數字只含 renderer 提交，非完整輸入／動畫耗時；不支援 GPU timer 的裝置只回報 CPU 與繪製量。

## 車模、燈光與懸吊精修

五款短車使用分段曲面車身，區分跑車低車頭、轎車弧肩、越野車與皮卡較直立的輪廓。九款車增加開口輪拱、不同輪圈輻條、胎紋與排氣口；短車的車窗採開放殼體，內部有座椅、儀表台及方向盤。巴士／校車增加通風與逃生艙口，貨車增加車頂壓筋。模型仍在 Blender 依材質合批，輪胎細節維持同一滾動批次。

道路紋理包含骨材、修補色差和細裂紋，同時控制微小凹凸與粗糙度；地面有柔和色調漸層，日／黃昏曝光重新調整。夜景車燈以單一合批平面呈現地面光束，依前方車輛及場地邊界縮短；它是受遮擋範圍限制的光照視覺近似，並非額外投影燈或體積光。圍欄改為上下圓管、柱帽與固定底座，樹冠有不同葉色。

九款車使用不同懸吊頻率及加速度反應，跑車較緊、露營車較柔。車身有獨立的臨界阻尼垂直壓縮，原始壓縮限制為 0.006 格，車身動態滑桿會一起縮放；輪胎與格位始終維持貼地。此為格位控制下的車身物理回饋，沒有自由剛體或輪胎摩擦求解器。測試檢查九款車在 30/60/120 Hz 的壓縮範圍、單側接觸與回正；觸控整合測試另驗證接觸時懸吊壓縮、輪胎不傾斜、位置不變。

`node scripts/verify-art.mjs <CDP-WebSocket-URL>` 以隔離 localhost:4173 Chrome 截取 55°／25° 日景、55°／-20° 黃昏與 375px 夜景，驗證每個場景的 24 個車身命中位置及無橫向溢出，並還原進度與偏好。截圖放在忽略的 `.browser-checks/`，需實際查看圖片以確認美術。

精修後重新量測：日景標準畫質待機繪製呼叫中位數 68、拖曳 124，拖曳三角形中位數 166,974（含陰影），仍較 6930778 的 262,054 少約 36%；夜景拖曳呼叫中位數 125。相同短時量測的日景 CPU 提交 p95 為 1.0 ms，GPU p95 為 10.08 ms。這是目前測試環境的樣本，並非所有裝置或所有關卡的效能保證。新增細節增加幾何量，後續美術仍須配合此量測流程。

## 主角跑車與遊玩構圖

主角跑車以 [Ferrari 296 GTB 的造型資料](https://www.ferrari.com/content/dam/ferrari-fcom/news/corporate/2025/12/pdf/CS_296_GTB_final_gbr_latest.pdf) 為參考，重建連續曲面車殼、低車鼻、隆起的弧形葉子板、環繞式座艙、後方支撐線條與引擎蓋。移除中線條紋與方塊飾件，輪槽直接開在車殼側面；細長頭燈依曲面射線結果定位。沿用原車漆、車燈與飾件批次。

`scripts/render_hero.py` 用 Blender 從實際匯出的 GLB 產生單車斜角／側面驗證圖，輸出至 `.browser-checks/coupe-three-quarter.png` 與 `coupe-side.png`。需先執行素材產生腳本，再用相同 Blender 命令執行此渲染腳本。模型測試另以射線確認引擎蓋中央沒有被輪槽切穿，四個輪拱上方包覆輪胎。

前輪流線車殼版本的 GLB 為 277,800 bytes。標準日景拖曳繪製呼叫中位數仍為 124，三角形 167,502；CPU 提交 p95 1.3 ms、GPU p95 7.86 ms，屬本次短時樣本，不能直接視為跨裝置幀率保證。模型測試亦檢查左右 LED 鏡片露在燈罩上方，單車渲染與六種實際遊戲構圖已查看，觸控通關與待機快取通過。

## 掀背小車與越野車

小轎車重建為圓潤掀背曲面、拱形車頂、玻璃天窗、後窗與尾翼；越野車採較高直立座艙、雙車頂縱桿、後置備胎、五條格柵與下護板。兩款皆使用連續車殼、真實輪槽開口、分區玻璃與車身同色後視鏡。輪拱飾板與門把依車殼射線結果貼合，保留原本格位、輪距、滾動動畫與材質批次。

以 `blender --background --python scripts/render_hero.py -- compact` 或 `-- jeep` 產生對應單車斜角／側面 GLB 驗證圖。模型測試確認葉子板內外側包覆輪胎、輪槽沒有切穿車頭、兩款車頂高度有區別，以及合批後包圍盒不變。實際 Chrome 驗證六種視角各 24 個抓取樣本、觸控受阻／吸附／取消、三種畫質與第一關九步通關，待機約 30 FPS、零陰影更新，離屏零繪製。

掀背／越野車重建時的標準畫質拖曳短時量測：日景／夜景／手機夜景 CPU 提交 p95 為 0.8／1.0／0.9 ms，GPU p95 為 10.40／11.59／11.30 ms。繪製呼叫 p95 皆為 137，日景三角形 p95 172,082，相對前輪 167,970 增加約 2.4%；含陰影更新的影格會比使用快取的影格多繪製。GPU 時間受主機狀態影響，這次量測不能推論全面效能改善；手機仍為桌面 Chrome 模擬。

三款精修車的引擎蓋改為中央微拱、兩側平順降低的橫截面，修正高葉子板造成的中間凹陷感，保留輪胎包覆和原本車長／輪距。越野車輪拱飾板只保留有車殼支撐的段落，避免末端懸空。模型測試以三個縱向位置的橫向射線檢查中央沒有下陷，並保留車頭完整性與輪胎包覆檢查；修改後三款單車渲染與六種遊戲構圖已檢查。

鏡頭依實際佔用的不同高度區域取景，避免用整個街角最高點建立過大的空盒。桌面保留完整街角；手機直向優先放大停車場，允許周邊街道裁切，完整 6×6 解謎區仍在畫面內。手機畫布採正方形，場景與選車／設定保持同組，減少場景內上下留白。

視覺腳本另檢查 375px 新預設視角、320px 的 45°／35° 與 80°／-35° 極端視角。每種構圖檢查 24 個車身位置、四個解謎區角落及無橫向溢出。觸控九步通關、取消與畫質切換仍另行驗證。

上一輪主角與構圖更新後的標準日景拖曳量測為 124 次繪製呼叫、167,654 個三角形中位數；CPU 提交 p95 1.0 ms，GPU p95 11.20 ms。繪製呼叫維持上一輪同級，新增主角幾何使三角形略增；GPU 時間仍受測試環境影響。六種構圖的 144 個車身命中、完整四角、真實觸控九步通關與待機／離屏停繪已驗證。
